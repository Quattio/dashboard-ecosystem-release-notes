# Quatt Ecosystem Release Notes — dashboard

**Repo:** `Quattio/dashboard-ecosystem-release-notes` · **Live:** https://dashboard-ecosystem-release-notes.pages.dev (Google OAuth, quatt.io only)

Static, manifest-driven dashboard for Quatt ecosystem release notes (CiC + Cloud + App + Thread/Wireless Platform). One self-contained page per release wave, three audience tiers (Customer EN/NL, Internal, Engineering), styled per the `quatt-visual-branding` design tokens. The **Internal and Engineering tiers group tickets by their Jira parent epic**; the Internal tier tags each ticket with a colour-coded owning-**Team** pill, and the Engineering table colour-codes each epic group (`releases/_template.html` is the canonical current-format template).

## Structure

```
index.html               Shell — renders releases.js at load, never edited per release
releases.js              Manifest: one entry per release wave (newest first) + summary stats
styles.css               Shared Quatt-branded stylesheet (light default, dark mode toggle)
functions/
  _middleware.ts         Google-OAuth gate (quatt.io only) on every route
  api/create-session.ts  Verifies the Google ID token, sets the session cookie
  api/calendar.ts        Serves the shared release calendar (secret iCal feed) as JSON for the live timeline
releases/
  DD-MM-YYYY.html        Self-contained page per release (tabs + embedded ticket data + live release timeline)
```

## Workflow

Pages and manifest entries are generated by the `/release-notes` skill (Step 8) every release (~bi-weekly): GitHub tags → commit walk → Jira cross-reference → three tiers. Deploy by pushing to `main` — Cloudflare Pages auto-deploys to https://dashboard-ecosystem-release-notes.pages.dev (Google OAuth, quatt.io accounts only). The CF build runs `cf-pages-build.sh`: npm install (for the `jose` dependency of the auth functions) + copy of the static files into `dist/`.

**Live release timeline.** Each page renders a release timeline from the shared Quatt release calendar via `functions/api/calendar.ts` → `/api/calendar` (behind the quatt.io auth). It reads the calendar's **secret iCal address** from the Cloudflare Pages secret `RELEASE_TIMELINE_ICS_URL` (Settings → Environment variables & secrets). Until that secret is set the timeline section stays hidden; the feed URL is never committed.

The previous contents of this repo (Quatt internal-tool React template) are preserved in git history prior to the "Replace template with static release-notes dashboard" commit.
