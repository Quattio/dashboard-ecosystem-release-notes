# Quatt Ecosystem Release Notes — dashboard

**Repo:** `Quattio/dashboard-ecosystem-release-notes` · **Live:** https://dashboard-ecosystem-release-notes.pages.dev (Google OAuth, quatt.io only)

Static, manifest-driven dashboard for Quatt ecosystem release notes (CiC + Cloud + App + Wireless Platform). One self-contained page per release wave, three audience tiers (Customer EN/NL, Internal, Engineering), styled per the `quatt-visual-branding` design tokens.

## Structure

```
index.html               Shell — renders releases.js at load, never edited per release
releases.js              Manifest: one entry per release wave (newest first) + summary stats
styles.css               Shared Quatt-branded stylesheet (light default, dark mode toggle)
releases/
  DD-MM-YYYY.html        Self-contained page per release (tabs + embedded ticket data)
```

## Limits tab

Each release page can carry a fourth tab — **Limits** — with the product limits / thresholds / targets
extracted from `quatt_controller` (and `quatt-heatcharger-firmware`) at the release's firmware tags.
Rows whose value changed vs the previous release's tag are highlighted, and symbols that no longer
resolve are greyed out with an explicit "symbol not found" marker (useful drift signal for Signal/TCS).

Generate (idempotent — safe to re-run on a page that already has the tab):

```
GITHUB_TOKEN=<token with read access to Quattio/quatt_controller> \
node tools/generate-limits.mjs \
  --page releases/2026-06-30.html \
  --cic 4.8.1 \
  --controller-tag 6.9.2 \
  --prev-controller-tag 6.9.0 \
  --heatcharger-ref main
```

The symbol → table-row mapping lives in `tools/limits-spec.json`; when firmware moves or renames a
constant, update the spec (files, `scope` struct fallbacks, or `symA|symB` alternatives). Offline
self-test with fake-value fixtures (no token, no network): `npm run limits:test`.

This step slots into the `/release-notes` skill as part of Step 8, after the release page is written.

## Workflow

Pages and manifest entries are generated by the `/release-notes` skill (Step 8) every release (~bi-weekly): GitHub tags → commit walk → Jira cross-reference → three tiers. Deploy by pushing to `main` — Cloudflare Pages auto-deploys to https://dashboard-ecosystem-release-notes.pages.dev (Google OAuth, quatt.io accounts only). The CF build runs `cf-pages-build.sh`: npm install (for the `jose` dependency of the auth functions) + copy of the static files into `dist/`.

The previous contents of this repo (Quatt internal-tool React template) are preserved in git history prior to the "Replace template with static release-notes dashboard" commit.
