    QPD-7154 · SW&I Technical Debt 11 tickets

    The SW&Infra technical-debt Epic (app + backend). This wave is almost entirely app modernization: adopting the React Compiler, removing legacy libraries and screens, and optimising image assets.

    • App modernization: adopt the React Compiler app-wide (QPD-11699 App); remove react-native-elements (QPD-15104 App); remove the deprecated DatePicker / DateTimePickerModal (QPD-13096 App); migrate InstallerConfiguration sliders to the shared Slider (QPD-15261 App); import TanStack query hooks directly (QPD-15287 App); flatten the Welcome/Home stacks into the RootStack (QPD-15318 App)
    • Legacy cleanup: Insights V2 cleanup — remove the insights_v2 flag, legacy Insights code and victory-native-legacy (QPD-14883 App); relocate remaining legacy assets and delete src/legacy (QPD-14774 App)
    • Assets & observability: optimise image assets (lossless compression, drop legacy tiers) (QPD-14941 App) with a CI workflow to auto-optimise images in PRs (QPD-15254 App); report feature-flag evaluations to Sentry (QPD-11845 App)
    Impact for ops: internal app refactoring — no field action.

    Impact for ops: internal build tooling — no field impact.

    QPD-152 · Production Incidents / Continuous Improvements — App / Backend 7 tickets

    Quatt’s rolling maintenance Epic: every ticket traces back to a production issue. This wave it carries worker hot-path optimisations, a dashboard health-check fix, a data backfill, a data-source migration and two app fixes.

    • Worker performance: stop reading the Redis lastStat twice per stats message (QPD-14884 Cloud / Backend) and skip the forgotten-Wi-Fi lookup unless the reported SSID differs (QPD-14886 Cloud / Backend)
    • Dashboard & data: fix the CIC health check that wrongly flagged every Chill / All-Electric CIC as an error (QPD-14809 Cloud / Backend); backfill installation.boilerType for mismatched installations (QPD-14147 Cloud / Backend); migrate the EEX gas-pricing data source from sFTP to EEX File Cloud (QPD-14336 Cloud / Backend)
    • App fixes: stop the thermostat card rendering shorter than Chill cards on the home screen (QPD-15311 App); fix add-installation product images rendering oversized on iOS (QPD-15310 App)
    Impact for CS: the health-check fix (QPD-14809) clears a false “error” state for every Chill / All-Electric CIC on the CS dashboard. The home-screen card-height fix is customer-visible (see the Customer tab); the other items are backend/setup only.

    QPD-7060 · Migrate hybrid commissioning to new architecture 6 tickets

    Migrating hybrid commissioning onto the more robust All-Electric architecture and tearing down the legacy system. This wave is backend teardown and data migration.

    • Legacy teardown: deprecate + gate all 42 legacy commissioning endpoints and stop legacy DB writes (QPD-7267 Cloud / Backend); migrate the old commissioning system in the DB to the new one (QPD-7274 Cloud / Backend); remove the old commissioning endpoints and code (QPD-7275 Cloud / Backend)
    • Data backfill & tests: backfill the remaining 719 legacy commissionings (no-installer + cancelled/failed) into the new table (QPD-15349 Cloud / Backend); guard against a duplicate HYBRID migration mirror on repeated CHILL commissioning (QPD-14449 Cloud / Backend); migrate the e2e / test infrastructure off the legacy flow (QPD-14896 Cloud / Backend)
    Impact for installers / CS: the legacy hybrid commissioning path is being fully retired in favour of the HYBRID_BETA flow. Backend and data migration only — no installer action.

    QPD-11732 · All-E | Boost Mode Feature 4 tickets

    Boost Mode lets an All-Electric system quickly restore hot water for at least one shower when the HeatBattery is depleted. This wave finalises the app rollout and adds status reporting for the “waiting for the controller” phase.

    • App: remove the all_e_boost_mode feature flag and the legacy V1 HeatBattery screen (QPD-14724 App); handle the new AWAITING_CIC_STATE status and show a “takes longer” banner on STARTING (QPD-15257 App); soften the bottom-tank-hot banner (remove the warning icon, reword the copy) (QPD-15322 App)
    • Backend: add the AWAITING_CIC_STATE status to distinguish “waiting for controller” from the controller’s own STARTING state (QPD-15256 Cloud / Backend)
    Rollout being finalised — confirm before communicating: the app flag is removed in v1.60.0, but All-Electric Boost Mode’s availability still depends on the backend production minimum-CiC-version gate. Confirm that gate before telling any customer Boost Mode is available on their All-Electric system.
    Impact for CS: do not promise All-Electric Boost Mode until the production version gate is confirmed set.

    QPD-138 · Quatt App ideas & improvements 3 tickets

    The app ideas-and-improvements backlog. This wave: customer-visible home-screen and settings polish.

    • Redesign the sound settings screen with stacked day / night sliders and a Night hours row (QPD-15101 App)
    • Prevent the home screen jumping while Chills load in (QPD-15307 App)
    • Fix the low-resolution HeatBattery product image (QPD-15309 App)
    Impact for CS: all three are customer-visible app polish (see the Customer tab) — sound settings, home screen and the HeatBattery image.

    QPD-14497 · CHILL | Charge HeatBattery with Chill 3 tickets

    “Charge Cool” charges an All-Electric HeatBattery from the waste heat a Chill produces while cooling. This wave refines the controller logic; the feature itself remains switched off in the field.

    • Charge Cool must stop upon hot-water draw-off (QPD-14981 Systems Control)
    • Align the Charge Cool end with the anti-legionella check conditions and add robustness to sensor defects (QPD-15105 Systems Control)
    • Prioritise Charge Cool over other charging when a Chill is actively cooling (QPD-14985 Systems Control)
    Shipped but DISABLED — do not communicate: Charge Cool is gated off fleet-wide (the cloud flag is off and the controller double-gates on a Redis enable key plus a HeatCharger being present). These are refinements to a feature customers cannot reach yet.
    Impact for CS: no customer action — Charge Cool is not live.

    QPD-11795 · CHILL | Field Test Stability Improvement 2 tickets

    Stability work for Chill pilot installations — fixing Chill and dongle connectivity bugs that fall outside current feature development.

    • Recover a managed dongle stuck in a non-secure CoAP loop by re-initiating the update flow after a routing change, so a re-identified dongle returns to a secure connection (QPD-14843 Embedded Systems)
    • Report a connected dongle awaiting its mesh address as POOR (not DISCONNECTED) and recover observe subscriptions reliably, so a healthy session is no longer torn down every ~60 s (QPD-14523 Embedded Systems)
    Impact for CS / installers: improves Chill / dongle field-connection stability on pilot installations and removes spurious disconnect states.

    QPD-11880 · Bug Fixing & Fleet Diagnostics 3 tickets

    The controls / embedded rolling bug-fixing and fleet-diagnostics Epic. This wave: the beta.1 OpenTherm room-thermostat fix, a controller protection fix and faster LTE-modem recovery.

    • beta.1 fix — the A926 OpenTherm Smart Power offload introduced this wave regressed room-thermostat connectivity on the beta cohort: 11 of 89 beta CICs with a Honeywell or Remeha thermostat lost thermostat communication on beta.0. beta.1 reworks the Smart Power handshake and bit-timing (“ladder”) windows on the room-thermostat bus and adds diagnostics and recovery knobs to fix it. The boiler side was never affected. (QPD-15498 Embedded Systems)
    • The controller now reacts to the AT (high / low) pressure-switch protection flags via new watchdog code (QPD-14976 Systems Control)
    • Drive the modem’s BOOT_CFG pin to recover a faulty modem, with dedicated MODEM-RECOVERY logs and a faster recovery timeout (a stuck modem now resets in ~40 s instead of several minutes) (QPD-15120 Embedded Systems)
    Impact for CS / installers: on the beta track only — a beta.0 build could drop the room-thermostat connection on Honeywell / Remeha thermostats, and beta.1 fixes it; the general fleet on 4.10 was never affected. Do not promote 4.11 further until the fix is confirmed on Honeywell + Remeha rigs. The controller also now responds to a pressure-switch protection trip, and CICs recover a stuck LTE modem faster (greppable in Axiom: MODEM-RECOVERY).

    QPD-14553 · ALL-E | Charging tank with Chill validation (Charge Cool) 2 tickets

    Surfacing why the HeatBattery is charging, including the Chill (Charge Cool) source, across backend and app.

    • Expose the HeatBattery charging reason on the All-Electric status response (QPD-15314 Cloud / Backend)
    • Show the HeatBattery charging reason (anti-legionella / Chill) on the HeatBattery screen (QPD-15330 App)
    Partially dormant — do not over-communicate: the Chill part of the charging reason depends on the gated Charge Cool feature (see QPD-14497), so the “charging with Chill” reason will not appear until Charge Cool is enabled. The anti-legionella charging reason is live.
    Impact for CS: the HeatBattery screen can now explain why the battery is charging; the Chill-driven reason stays dormant while Charge Cool is off.

    QPD-186 · All-E | Systems Engineering & Hardware Development 1 ticket

    All-Electric systems-engineering Epic. This wave: a backend guardrail on the custom night window, shipped in Cloud v2.43.1.

    • Reject a custom night window that leaves less than 6 hours of day, so the anti-legionella cycle (which is skipped during the night window) still has room to run. The backend now returns 400 DAY_TOO_SHORT on such a window; existing stored windows are left untouched (QPD-15520 Cloud / Backend)
    Impact for CS: a customer setting an over-long night window (leaving under 6 h of day) now gets a clear rejection instead of silently starving the anti-legionella cycle. The matching in-app dial limit ships in a later app version.

    QPD-12956 · CHILL/DONGLE | Apply for Thread Certification 1 ticket

    Bringing the CiC’s Thread stack up to Thread-certification requirements.

    • Apply Thread-certification remarks to cic-thread-network-manager: enable the DHCPv6 client and Vendor Diagnostic TLVs (QPD-15355 Embedded Systems)
    Impact for ops: Thread-certification compliance work on the CiC — no field-visible change.
