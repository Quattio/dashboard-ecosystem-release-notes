What changed in this revision

Shown only on the staging preview — hidden in production.

Promotion beta.0 → beta.1, plus a newly-paired app release. This revision updates the 4.15.0 wave from its published entry (CiC 4.15.0-beta.0) to CiC 4.15.0-beta.1. The CiC image gains one commit on top of beta.0 (a cic-mender-tools bump), and the mobile-app release App v1.63.0 (published 2026-09-25) has since landed inside the wave’s alpha→beta window and is now folded in.

  • Phase transition: beta.0 → beta.1 (tag suffix -beta.0 → -beta.1 on the 4.15.0 minor). Badge stays beta.
  • Headline date: moved 2026-09-23 → 2026-09-29 — the 4.15.0-beta.1 GitHub Release’s published_at. The page has been renamed 2026-09-23.html → 2026-09-29.html (one page per wave).
  • Paired-product version bumps: App v1.62.0 → v1.63.0 (new, 2026-09-25). Cloud stays v2.48.0. In the CiC image, cic-mender-tools 1.2.1 → 1.2.2; all bundled firmware unchanged from beta.0 (Chill CB FW 2.0.1, Controller 6.14.0, Thread FW 2.14.0, HeatCharger FW 1.3.0, ODU FW 2.1; embedded apps 1.37.1, message spec 2.85.2, network-monitoring 1.5.1, controller-manager 3.19.2).
  • Newly-added tickets since the wave’s previous tag (4.15.0-beta.0):
    • App v1.63.0 (27 tickets): the predictive-heating app UI — thermostat schedule screen and heating-options toggles, gated on predictiveHeatingEnabled (QPD-15714, 15818, 15819, 15830, 15831, 15855, 15861, 15862, 15871, 15928, 15942, 15948, 15954); WiFi-connect feedback rework and legacy-screen removal (QPD-15538, 15639, 15640); an installer “update available” banner (QPD-15796, 15798); a Dutch dongle-pairing title fix (QPD-15814); two homeowner-visible chart fixes (QPD-15844 legend overlap, QPD-15854 Android axis labels); the watchdog commissioning alert in-app (QPD-15974); Mijnbatterij battery-results sharing (QPD-15695); Virtual Quatt phase 1 QE tooling (QPD-15122); a tech-debt flag removal (QPD-15696); and an OpenAPI type regeneration (QPD-15952).
    • CiC image (no QPD key): cic-mender-tools 1.2.2 blocks starting new Mender OTA downloads while the CiC is on LTE (a download already started on WiFi still resumes), preventing multi-GB-per-day LTE data use from a repeatedly-failing deployment. This is a follow-up to the 4.15.0 network-monitoring change that keeps mender-updated running on LTE. Cut as cic-mender-tools PR #12 with no Jira ticket.
  • Reverted / removed: nothing.

Enablement sweep (re-run for beta.1): predictive heating (QPD-15828 / QPD-15847) remains enabled for the pilot cohort only; the App v1.63.0 predictive-heating UI is gated on predictiveHeatingEnabled, so it is reachable only by pilot participants. Reactive avoid-gas-boiler (QPD-16006) stays on develop only. Charge Cool remains live fleet-wide (already communicated). No new fleet/config rollout landed between the beta.0 and beta.1 tags.

    QPD-11880 · Bug Fixing & Fleet Diagnostics 4 tickets

    The embedded team’s rolling bug-fixing and fleet-diagnostics Epic. This wave: a factory-reset fix, a config-delivery fix, message-spec robustness, OTA retry backoff, and (in beta.1) blocking new Mender downloads over LTE — all riding the CiC 4.15.0-beta.1 build.

    • Factory reset fixed: quatt-factory-reset used an invalid systemctl stop --timeout option, so it never actually stopped the owner services during a factory reset — corrected (QPD-15989 Embedded Systems)
    • Config delivery fixed: nested config objects (e.g. the predictive-heating dual-rate model) were never written to their Redis key, so the controller never received them — fixed in controller-manager 3.19.2 (QPD-16011 Embedded Systems)
    • Message-spec robustness: ensure new settings / configs are nullable, so the cloud can send an unset value without the whole payload being rejected (message spec 2.85.2) (QPD-15929 Embedded Systems)
    • OTA retry backoff: OTA update-cycle retries had no delay, so 20 cycles could burn in ~2 seconds and turn a transient “not now” into a permanent failure — the OTA library now backs off between retries (bundled via embedded apps 1.37.1) (QPD-15978 Embedded Systems)
    • Block new Mender downloads over LTE (beta.1, no ticket): since 4.15.0 the CiC keeps mender-updated running on LTE when a WiFi profile is saved, so a repeatedly-failing deployment could restart new downloads over LTE (up to a few GB per CiC per day). cic-mender-tools 1.2.2 makes the download-enter check return “retry” unless Ethernet or WiFi is reachable; a download already started on WiFi still resumes over LTE (cic-mender-tools PR #12, no QPD key)
    • Diagnostics (no ticket): every Axiom log record is now stamped with the CiC version, so fleet logs are attributable to a firmware version
    Impact for ops: these fix real field and diagnostic failure modes (factory reset not stopping services, config not reaching the controller, OTA updates failing instantly, and runaway LTE data use from repeated failed downloads). They ride the CiC 4.15.0-beta.1 build, so they reach the beta track first, not the general fleet, this wave.
