Release timeline

Live from the shared Quatt release calendar.

    This ecosystem update centres on a CiC 4.12.0 alpha firmware build, which goes to a small internal test group and is not installed on the customer fleet. The customer-visible changes below arrive with the Quatt app update (version 1.61.0), which is available to everyone.

    New functions

    • The Quatt app now supports push notifications. If you have a Chill, you’ll get an alert when its water reservoir is full and needs emptying. You can turn notifications on or off in the app’s notification settings.
    • You can now copy your user ID from the app’s information screen — handy when you contact Quatt support.

    Heating performance and reliability

    • Everyday heating and comfort behaviour is unchanged in this release.

    Bug fixes and maintenance

    • Fixed an issue on recent iOS versions where the HeatBattery tab could show a blank screen and overlap the Insights tab.
    • Smoother navigation and general reliability and maintenance improvements.

    Enablement sweep — what actually goes live this wave

    • Push notifications go live. The backend enables push in production (QPD-15372); the first trigger is a Chill tank-full alert on the high-water-level switch (QPD-15368); the app-side UI (permission flow, notification settings, Chill enable-CTA, deep links) ships in v1.61.0. Customer-visible — see the Customer tab.
    • Custom night hours fully rolled out. The app removes the custom_night_window feature flag (QPD-15057), and a server-side guard now rejects night windows that leave less than 6 h of day so anti-legionella still fits (QPD-15520, QPD-15521). The feature itself was already announced with app v1.60.0 in the 4.11.0 wave — not a new customer feature here.
    • Weather platform V1 (backend groundwork). Cloud v2.44.0 plus controller-manager 3.19.0 add KNMI forecast import, per-postcode retained MQTT delivery to the CiC, and forecast forward-fill on the insights temperature graph — foundation for predictive heating and solar optimisation, not surfaced as a standalone customer feature yet.
    • The alpha CiC firmware (control-mode-switch fix, boost-mode hardening, ODU OTA robustness, dynamic stats interval) goes to alpha testers only — do not communicate its behaviour to the wider customer base or installers.

    QPD-152 · Production Incidents / Continuous Improvements — App / Backend 13 tickets

    Quatt’s rolling maintenance Epic: production issues are raised as NCRs by the Quality team and fixed here, priority-driven with no target date. This wave it carries an iOS app bug fix, backend cost/perf and clean-up work, and admin tooling.

    • Customer-facing app fix: the HeatBattery tab could render blank and overlap the Insights tab on recent iOS versions — fixed (QPD-15359 APP)
    • App maintenance: React Native upgraded to 0.86 (QPD-15331 APP); copyable user ID on the App-information screen (QPD-15492 APP); night-hours dial now enforces the server minimum day length (QPD-15521 APP); drop the strict Wi-Fi SSID equality check during pairing (QPD-14124 APP); show waterFlowSwitch3x as “10x” on the commissioning Diagnostics screen (QPD-15354 APP)
    • Backend cost / performance: reduce ClickHouse read volume via sort-key predicates and removing full-table scans (QPD-15483 Cloud / Backend); gate MQTT debug Redis publishes on active subscriptions (QPD-15487 Cloud / Backend)
    • Backend clean-up: remove the deprecated Enercalc energy-price provider (QPD-15475 Cloud / Backend); remove dead production code kept alive only by its own tests (QPD-15476 Cloud / Backend); move EEX gas-pricing cron onto File Cloud (QPD-14336 Cloud / Backend)
    • Support / admin: new admin user list/search + detail endpoints (QPD-15411 Cloud / Backend); display waterFlowSwitch3x as “Water Flow Switch 10x” in Chill fault-flag titles (QPD-15351 Cloud / Backend)
    Impact for CS: the iOS HeatBattery-tab fix (QPD-15359) is customer-visible (see the Customer tab). Everything else is backend maintenance/perf or admin tooling with no customer action; the diagnostics/fault-flag label changes are installer- and dashboard-side only.

    QPD-10390 · CHILL | SW Improvements 7 tickets

    This wave this Epic carries the backend of push notifications, which goes live in Cloud v2.44.0. The send pipeline, per-device localisation and the first customer trigger all ship here; the app-side UI is under the App Epic below.

    • Send pipeline: FCM service, BullMQ send job and env flag (QPD-14797 Cloud / Backend), with send-attempt logging (QPD-15367 Cloud / Backend)
    • First trigger: a Chill tank-full alert fired on the high-water-level switch (QPD-15368 Cloud / Backend)
    • Localisation & correctness: extend push-token registration with the app language (QPD-15369 Cloud / Backend) and localise the payload per device language/platform (QPD-15370 Cloud / Backend)
    • Ops: an admin test-send endpoint (QPD-15371 Cloud / Backend); enable and observe push in production (QPD-15372 Cloud / Backend)
    Impact for CS: push notifications are now live in production (see the Customer tab). Today the only automatic message is the Chill water-reservoir-full alert; a customer who mentions receiving app notifications for their Chill is expected behaviour. Notifications can be toggled by the customer in the app’s notification settings. The admin test-send endpoint (QPD-15371) lets support verify delivery.

    QPD-138 · Quatt App ideas & improvements 7 tickets

    The app ideas-and-improvements backlog. This wave it holds the app-side of push notifications (the counterpart to the backend Epic above) plus two smaller polish items.

    • Push notifications (app): permissions, token lifecycle and Android setup (QPD-15332 APP); a notification settings screen in app settings (QPD-15364 APP); an enable-notifications CTA on the Chill control screen (QPD-15365 APP); deep-link routing and the payload contract with the backend (QPD-15366 APP); switch to the right installation when a notification tap concerns another house (QPD-15431 APP)
    • Polish: fade in the navigation-header background on scroll (QPD-15481 APP); remove the now fully-rolled-out custom_night_window feature flag (QPD-15057 APP)
    Impact for CS: the notification settings screen and the Chill enable-CTA are the customer entry points for push notifications (see the Customer tab). Custom night hours is now on for all users (the flag removal completes its rollout); it was already announced with app v1.60.0.

    QPD-11880 · Bug Fixing & Fleet Diagnostics 7 tickets

    The controls and embedded teams’ rolling bug-fixing and fleet-diagnostics Epic. This wave’s controller work lands in the CiC 4.12.0 alpha firmware (alpha-tester track only).

    • Control stability (alpha firmware): fix rapid supervisor control-mode switching on single-ODU systems (QPD-15358 Systems Control); keep counting central-heating power/energy when the HeatCharger is disconnected (QPD-15357 Systems Control); handle ODU state transitions gracefully on noisy room-temperature readings (QPD-15361 Systems Control); harden All-Electric boost mode against a faulty/missing discharge saturation temperature (QPD-15413 Systems Control)
    • Connectivity & OTA (alpha firmware): recover ODU firmware transfer over a noisy Modbus bus (QPD-14690 Embedded Systems); validate/sanitise the modem identity before publishing it to Redis (QPD-15315 Embedded Systems); stop the modem emitting network-time URCs (QPD-15426 Embedded Systems)
    Impact for CS / ops: these are controller and connectivity improvements in the alpha CiC firmware — they are on the alpha-tester track and not yet on the customer fleet, so present none of them as live customer behaviour. The single-ODU mode-switch and noisy-room-temperature fixes are the ones to watch when the 4.12 line later promotes to the fleet.

    QPD-11732 · All-E | Boost Mode Feature 4 tickets

    Boost Mode lets an All-Electric system quickly restore hot water for at least one shower when the HeatBattery is depleted. This wave refines its reporting across the controller, backend and app.

    • Controller (alpha firmware): improved, energy-based shower-minutes estimation (QPD-14716 Systems Control); complete boost exit-reason and recoverable-condition reporting (QPD-15024 Systems Control)
    • Backend + app: map boost exit-reason 11 (three-way valve unavailable) so the app can show a 3-way-valve banner on a failed boost (QPD-15263 Cloud / Backend / APP); version-gate the temporary shower-minutes bonus behind the new energy-based CIC floor (QPD-15405 Cloud / Backend)
    Impact for CS: the controller-side improvements ride in the alpha CiC firmware (alpha testers only). The 3-way-valve banner gives a clearer reason when a boost cannot complete because of the valve — relevant on All-Electric systems where Boost Mode is enabled.

    QPD-11795 · CHILL | Field Test Stability Improvement 3 tickets

    Impact for CS / installers: Chills can no longer be set to an invalid 16 °C target, and support can import Chills into inventory from the dashboard.
