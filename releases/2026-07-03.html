Quatt Ecosystem Release 03.07.2026

CiC 4.9.0 Cloud v2.41.1–v2.41.2 Controller 6.10.2 Thread FW 2.12.0 Chill CB FW 2.0.0 ODU FW 2.1

What changed in this revision

Shown only on the staging preview — hidden in production.

Phase promotion: beta → stable (GA). The 4.9.0 wave graduates from the 4.9.0-beta.0 pre-release to the general 4.9.0 release for the fleet. The 4.9.0 GA tag points at the same commit (b70b8856) as 4.9.0-beta.0 and 4.9.0-alpha.0 — this is the beta build promoted to GA, not a rebuild.

  • Badge / version: beta → stable (GA); CiC 4.9.0-beta.0 → 4.9.0 across the page and manifest.
  • Newly-added tickets since the previous tag (4.9.0-beta.0): none — GitHub reports no commits between 4.9.0-beta.0 and 4.9.0, so the ticket table is unchanged (45 entries).
  • Paired-product versions: unchanged — bundled Controller 6.10.2, Thread FW 2.12.0, Chill CB FW 2.0.0, ODU FW 2.1; paired Cloud v2.41.1–v2.41.2. No App build is paired.
  • Tier 1: the beta “not for the fleet” notice is removed (now a general release); the two fixed sections are unchanged and still report no day-to-day heating change.
  • Tier 2: scope callout updated from beta to GA. The ZipStats production-enablement callout (QPD-13788 + QPD-14293) and the held cross-product HeatCharger three-way-valve item (QPD-13979) are carried forward unchanged. Nothing reverted or removed.

Heating performance and reliability

  • This update focuses on the reliability of how your Quatt stays connected to the Quatt cloud, and lays the groundwork for future heating improvements. Everyday heating and comfort behaviour is unchanged in this release.

Bug fixes and maintenance

  • This update includes general reliability, connectivity and maintenance improvements.

Verwarmingsprestaties en betrouwbaarheid

  • Deze update richt zich op de betrouwbaarheid van hoe je Quatt verbonden blijft met de Quatt cloud, en legt de basis voor toekomstige verwarmingsverbeteringen. Het dagelijkse verwarmings- en comfortgedrag verandert niet in deze release.

Foutoplossingen en onderhoud

  • Deze update bevat algemene verbeteringen op het gebied van betrouwbaarheid, connectiviteit en onderhoud.
Scope: CiC 4.9.0 — the stable (GA) release for the fleet, diffed 4.8.1 → 4.9.0. The 4.9.0 GA tag points at the same commit as 4.9.0-beta.0 and 4.9.0-alpha.0: this is the beta build promoted to GA, with no code changes since the beta. Bundled firmware: Controller 6.9.2 → 6.10.2, Thread / Wireless Platform FW 2.11.1 → 2.12.0; ODU FW 2.1 and Chill control-board FW 2.0.0 are unchanged. Paired backend: Cloud v2.41.1 → v2.41.2 (v2.41.1 shipped 2026-06-30 and was deferred from the 4.8.1 hotfix to this wave). No App build is paired — v1.58.0 predates this window. Headline date 2026-07-03 = the date this build went public as 4.9.0-beta.0 (the 4.9.0 GA tag has no separate GitHub Release object; it repackages the same build).
Rolling out to the fleet: two flagship items below (predictive-heating groundwork, the rebuilt LTE stack) are shipped but not yet enabled in production. Do not communicate them to customers or installers until they are enabled.

1 · Cellular (LTE) connectivity — modem stack rebuilt on ModemManager / NetworkManager CIC | Connectivity

  • The SIM7070G cellular modem is now driven by ModemManager, and the mobile-data connection (ppp0) is owned by NetworkManager via a dedicated LTE profile. New helper services quatt-modem-setup (one-shot NV normalize) and quatt-modem-control (enable/watchdog bridge) replace the old quatt-ppp stack; the modem services now run as non-root users (QPD-14435)
  • Fix the modem booting in GSM-only mode — enable LTE Cat-M1 (and disable NB-IoT) on boot, which was the underlying cause of the earlier PPP flapping where the SIM's LTE data registration was denied (QPD-14264, QPD-14435)
  • New modem diagnostics dashboard tab for hardware (Betronic) testing (QPD-14455)
Impact for ops: this is a full rebuild of the cellular backup connectivity path. LTE had been switched off in an earlier wave (4.7.0-alpha) due to instability; this wave re-introduces it on a supported stack. Although the wave is now GA, the LTE data path is still gated and being rolled out cautiously. Confirm the fleet enablement state before telling any customer their unit uses LTE backup.

2 · ZipStats — compressed MQTT stats going to production CIC | Cloud Cost

  • The CiC now gzips its stats JSON on-device and publishes on the basic-ingest cicZipStats path (QPD-13788); the backend enables the production cicZipStats IoT rule / Kafka action via kafkaConfig (QPD-14293)
  • ~90% less AWS IoT Core message cost (~60 KB → ~6 KB; 12 → 2 billed chunks per publish). The inner { "stats": [...] } contract is unchanged, so downstream consumers are unaffected
Impact for ops: this feature is being enabled in production with this release. The firmware shipped in an earlier (4.8.x) wave, so what is new here is the fleet / production enablement — hence it is cited inline rather than as a row in the ticket table (which is strictly this wave's commit diff). Watch the production cicZipStats rule and the Parquet / SQS consumer output during rollout.

3 · Predictive heating — controller groundwork (MPC) Controls | Predictive Heating

  • Refactor the controller to be MPC-ready (Model Predictive Control interface) and add a mixed-integer quadratic-programming solver, including a binary switch for minimum heat-pump / ketel power (QPD-14137, QPD-14520)
  • Add offset correction driven by a state estimator + MPC model, support both hard and soft constraints per output, and surface the latest solver status (QPD-14517, QPD-14649, QPD-14650)
  • Add MPC analysis tooling to the controller simulator (QPD-14519)
Shipped but not live — do not communicate to customers: the controller now carries the predictive-heating machinery, but it is not enabled for the fleet. This is groundwork; there is no change to how any customer's system heats today.

4 · Chill fault-flag reset — CS tooling CHILL | Support Tooling

  • New “Reset fault flags” button in the CS dashboard for Chill devices, backed by the end-to-end path: the CiC now lets the backend reset a Chill's permanent fault, the backend exposes the reset command and a GET of the Chill's active fault flags for the confirmation pop-up (QPD-13799, QPD-14371, QPD-14645)
Impact for CS: support can now clear a Chill's stuck fault flags from the dashboard, with a confirmation step that shows which faults are currently active. Requires both this CiC build and the paired Cloud v2.41.1+ — both ship in this wave, so the feature is functional end-to-end.

5 · Commissioning & diagnostics Commissioning

  • All-Electric: faster preheat during the ODU test (QPD-14483); cooling test pump speed corrected to 5% (QPD-14626); tighter CH / DHW delta reference ranges for the charging-mode test (QPD-14324)
  • Surface live Chill faults as banners on the Chill commissioning test screens (QPD-14625), and add the Quatt Network (Thread) state to system diagnostics (QPD-14555)
  • All-E commissioning alerts: suppress two tank-filling false-positive warnings and add a “HeatCharger firmware updating” info alert (QPD-14558)
  • Fix the Support-Dashboard ‘Is commissioned’ health check showing red for Hybrid installs commissioned via the new (HYBRID_BETA) flow (QPD-14613)
  • Fix an All-Electric Duo conversion bug where the cloud published numberOfHeatPumps=1 during identification, so the CiC ran a single-ODU profile and the second heat pump was never energized (QPD-14619)
Impact for installers / CS: smoother All-Electric and Chill commissioning, fewer false alerts, and two health-check bugs (Hybrid “Is commissioned”, All-E Duo two-ODU) resolved. Several of these need the paired Cloud v2.41.1.

6 · Fleet firmware-deployment reliability CIC | Fleet Management

  • Fix Deploy-Latest CIC firmware doing nothing for any CiC above the 3.0.0 commissioning floor (it compared versions incorrectly and treated up-to-date units as needing no work) (QPD-14579, Urgent)
  • Fix a fleet-wide 500 when creating a firmware deployment, caused by a malformed Mender artifact name breaking the semver compare (QPD-14785); normalize the artifact version before comparing (QPD-14785)
  • Auto-trigger a Mender firmware deployment when a CiC's firmware is too old to commission (QPD-14485), and create better Mender deployment groups (QPD-14566)
  • Auto-detect an ODU firmware version change (e.g. after a board swap) and re-trigger the update (QPD-14693)
Impact for ops: two production-impacting deployment bugs are fixed — one that silently skipped firmware roll-outs and one that failed deployment creation fleet-wide. Firmware roll-outs should behave normally again.

7 · Environment sensors over Thread — data groundwork Wireless Platform | Sensors

  • The Quatt dongle now reads its on-board temperature / humidity sensor and reports it over CoAP /sensors; the CiC subscribes and publishes the readings (QPD-14458)
Impact for ops: begins collecting environment temperature / humidity from the dongle. Data-collection groundwork only — not yet surfaced to customers.

8 · Field reliability & bug fixes Bug Fixing & Fleet Diagnostics

  • Allow ICMPv6 ping over Thread (wpan0) through the firewall, restoring Thread certification test TC 9.2.x (QPD-14620, High)
  • The routine that clears stale persisted files after an over-the-air update now runs reliably and reverts cleanly if the update is rolled back (QPD-14287)
  • cic-chill now fails fast (marks the update failed) when a device goes unreachable mid-OTA during commissioning (QPD-14557); dongle recovers when it permanently lost the ability to communicate (QPD-14484, High); and a Chill in permanent fault now shows its fault LED (QPD-14206, High)
  • Guard cic-modbus-odu against crashing when the controller isn't alive (QPD-13768); fix Chill power-LED glitches and the isWorking/userOnState timing (QPD-13378, QPD-14169); count CH backup-heater power in the energy counters (QPD-13078)
  • Clearer CoAP off-mesh diagnostics (QPD-13761), network-monitoring test fix (QPD-14191), CVE / kernel package cleanup (QPD-13385), and backend maintenance — HomeBattery serial searchable in installation filters (QPD-14730) and a legacy Firehose pipeline cleanup (QPD-13944)
Impact for ops: a broad reliability sweep across Thread connectivity, Chill OTA robustness, energy accounting and backend housekeeping. No customer action required.
Held for a later wave: the CiC build also carries a three-way-valve error added to the HeatCharger system-error flags (QPD-13979). It does nothing until the paired HeatCharger firmware ships, which is not part of this wave, so it is omitted from these notes and will be covered in the release where it becomes functional end-to-end.
