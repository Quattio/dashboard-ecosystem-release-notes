What changed in this revision

Shown only on the staging preview — hidden in production.

This revision promotes the 4.17.0 wave from the 4.17.0-alpha.1 build (22.10.2026) to the first beta, 4.17.0-beta.0. The beta tag points at the same commit as 4.17.0-alpha.1 (e0fa6a0), so the firmware content is identical — only the release phase changes (alpha → beta). Delta since the previous revision:

  • Phase alpha → beta. The wave badge is promoted to beta and the CiC build moves from the alpha-tester track to the beta-tester track. It is still not on the general customer fleet.
  • No content delta. 4.17.0-beta.0 and 4.17.0-alpha.1 are the same commit, so no tickets, firmware versions or tier content changed since the alpha.1 revision. The 26 ticket rows / 16 unique QPD keys and all bundled-firmware versions are carried forward unchanged.
  • Headline date stays 2026-10-22. 4.17.0-beta.0 has no separate GitHub Release, so the date falls back to the tag commit’s committer date (2026-10-22) — the same commit as alpha.1, so the page filename and date are unchanged.
  • First production publication. Wave 4.17.0 has not yet reached main/production (the alpha PR is still open); when this PR merges, this is its first published revision.
  • Still CiC-only: no new paired App, Cloud or Wireless Platform release pairs with this wave (latest App v1.64.0 and Cloud v2.50.0 belong to the 4.16.0 wave).

Scope: CiC 4.17.0-beta.0 (beta track, not the general fleet), diffed 4.16.0 → 4.17.0-beta.0. Thread FW 2.15.0, HeatCharger FW 1.3.0 and Chill CB FW 2.0.1 are unchanged. 26 ticket rows / 16 unique QPD keys.

Enablement sweep (re-run for beta): the CiC - V4.17.0 Fix Version plus every paired-product Fix Version were swept again for enablement/rollout tickets with no commit in the tag diff. No new paired Cloud or App release pairs with this wave, so no production feature-flag flip or config rollout goes live for customers here. Predictive heating remains pilot-cohort only.

        Predictive heating (MPC) — continued pilot development 5 tickets

        Model Predictive Control for central heating: cloud-trained house models that let the controller plan ahead. This wave extends the predictive-heating engine on the controller and in the message spec. It remains a pilot-cohort capability and does not change how any customer’s system heats today.

        • Predictive heating now uses an external weather forecast as a model input, with the forecast output added to the message spec (QPD-14948 Systems Control)
        • Solve the condensed mixed-integer problem with the DAQP solver to reduce solve times (QPD-16248 Systems Control); low-level split of the boiler / heat-pump thermal power (QPD-15946 Systems Control)
        • Keep tracking the predictive-heating state while the MPC is off or the room temperature drops out (QPD-16182 Systems Control)
        • The state estimator resumes after a controller restart, with the estimator schema persisted and extended in the message spec (QPD-16100 Systems Control)
        Shipped but not live: predictive heating is not enabled for the fleet. It stays limited to the pilot cohort and does not change how any customer’s system heats today.
        Impact for CS: no customer-visible change and no field action.

        Service Tool and on-device service access point 3 tickets

        A new on-CiC field-service application ships in the 4.17.0 wave. cic-service-tool serves a web interface (EN/NL, credential login) that a technician reaches over a local service Wi-Fi access point managed by the new cic-access-point app. It is meant to streamline service, maintenance and new installations.

        • New cic-service-tool and cic-access-point apps added to the image: web UI with a system overview, per-device pages (heat pump / All-E, Chill, HeatCharger, boiler, thermostat) with live values and history, a Wi-Fi page, a Thread topology page, and a safety-timed manual mode that pauses the controller and releases control when the session ends (Embedded Systems)
        • The service access point CIC-<id>-service is opened by a 5-second button long-press and closes automatically after 60 minutes; its state drives the CiC LED (Embedded Systems)
        • The service access point now starts without waiting for the station to associate, so it comes up reliably (Embedded Systems)
        • Message-spec fields added for cic-service-tool and cic-access-tool (QPD-15839 Embedded Systems)
        Impact for field service / installers: a new local service interface exists on the CiC in this build, reached over a service Wi-Fi access point. It is new in this wave and is for service and installation use, not a customer feature. Do not present it to customers.

        ODU V2 and control robustness 5 tickets

        Controller robustness and ODU V2 handling: safer behaviour when components disconnect, corrected ODU V2 mapping, and the new ODU V2 firmware binaries validated on the pre-release track.

        • The controller handles null signals when components disconnect, instead of acting on missing values (QPD-15444 Systems Control)
        • Update the ODU V2 compressor frequency mapping for AMH6, and report PCB firmware below 2.0 for a simulated ODU V2 (QPD-16159 Systems Control)
        • Update the ODU V2 (AMH6 STM8) firmware and EEPROM binaries to 2.2 — new binaries from Amitime, validated. On the pre-release track only; it reaches the field by OTA in a later wave (Embedded Systems)
        • Adjust the central-heating maximum water-temperature range and keep the pump running at the limit (control-tuning change; no customer-perceivable comfort change claimed) (Systems Control)
        Impact for ops: internal robustness, ODU V2 test correctness, and a new ODU V2 firmware binary under pre-release validation. No field action; the water-temperature range change is control tuning, not a customer-visible setting.

        Connectivity — Thread / CoAP 2 tickets

        Reliability of the CiC-to-dongle Thread mesh. Stale service advertisements could keep the CiC retrying against sessions that no longer exist, and a double-reported OTA failure could leave a radio stuck on an older firmware.

        • Ignore expired SRP services and keep the CoAP restart backoff, so the CiC stops exhausting retries against dead sessions and avoids connection storms (QPD-16298 Embedded Systems)
        • Report a Thread OTA failure once and retry an exhausted OTA after a cooldown. A double-reported lost-link failure had burned both retries at once, which left two Chill radios stuck on Thread FW 2.14.0 after the 4.16.0 rollout (Embedded Systems)
        Impact for CS: fewer rare connection drop-outs between the CiC and its wireless accessories, and stuck firmware updates on connected radios now recover on their own. This is the fix summarised generically on the Customer tab.

        Telemetry and message specification 7 tickets

        Telemetry plumbing and message-spec maintenance: cleaner cloud payloads, a stats-publishing fallback fix, OpenTherm Smart Power flags that were hidden from userspace, and stricter enum typing. These tickets sit under several Jira epics (Chill temperature and humidity modelling, ZipIt telemetry, and CiC improvements).

        • Publish the device dew-point pair (QPD-14757 Systems Control)
        • When gzip fails, publish the uncompressed stats to cicStats, not cicZipStats (whose rule only parses gzip), so stats are not lost on a compression failure (QPD-16254 no team set)
        • Publish the A926 OpenTherm Smart Power handshake flags (OT_FT_SMART_POWER_IMPLEMENTED and OT_FT_MEMBERID_OF_MASTER) that the OpenTherm engine previously hid from userspace (QPD-16140 Embedded Systems)
        • Make commissioning mode and heat-pump test level proper enumerations; generate every custom cloud-data-type enum member (Embedded Systems)
        • Restore debug logging for the modem IMSI; stop sending unused telemetry fields to the cloud (~53 fields, about a 9% cut in cloud-sent fields) (Embedded Systems)
        Impact for ops: leaner and more robust telemetry. Modem-IMSI debug logging is available again; a forced-gzip-failure case no longer drops stats; the OpenTherm Smart Power flags are now visible in telemetry. The trimmed fields stay on the CiC and in historic data; only new cloud transmission stops.

        Persistence, deploy and test infrastructure 4 tickets

        Robustness of how on-device configuration and message-spec data are persisted, a fleet-deploy fix, and a test-harness fix. These tickets have no single parent epic.

        • The controller-manager persists message-spec JSON keys to their own file (QPD-16161 Embedded Systems), and the message spec validates where persisted rows live (QPD-16198 Embedded Systems)
        • The beta deploy now applies the fleet exclude list, so predictive-heating pilot CiCs are no longer pulled out of their Mender group by a beta rollout (QPD-16301 Embedded Systems)
        • Test harness: keep ssh_cmd output that arrives with or after the exit status (QPD-16288 Embedded Systems)
        Impact for ops: safer on-device persistence, a corrected beta-deploy exclude list for the predictive-heating pilot, and test robustness. No customer field action.
