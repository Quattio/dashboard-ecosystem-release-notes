    QPD-11732 · All-E | Boost Mode Feature 11 tickets

    Boost Mode lets an All-Electric system quickly restore hot water for at least one shower (within ~15 min) when the HeatBattery is depleted — heating speed over efficiency. This wave refines the round-trip UX, adds a security fix, and lands controller-side reporting.

    • Round-trip UX (backend, Cloud v2.42.0): optimistic Boost/Leave-Boost status (QPD-14742 Cloud / Backend), live All-Electric fields surfaced in the boost response (QPD-14222 Cloud / Backend), Live View on START/CANCEL (QPD-14788 Cloud / Backend), outcome tombstoning against a stale exitReason (QPD-14817 Cloud / Backend), time-based shower-minutes bonus while the tank sensor lags (QPD-14747 Cloud / Backend)
    • App + spec: read live All-E fields from the boost response instead of polling the CiC (QPD-14223 App); remove the never-emitted DEGRADED status across app, message spec and backend (QPD-14892 App, QPD-14299 Cloud / Backend)
    • Controller: complete boost-mode exit-reason and recoverable-condition reporting (QPD-15024 Systems Control)
    • Security: enforce CiC ownership on the /me boost action route (QPD-14740 Cloud / Backend)
    • Rollout: production minimum CiC version for boost stays at 4.9.0 — a bump to 4.10.0 was raised and reverted (QPD-15022 Cloud / Backend)
    Shipped but DISABLED — do not communicate: All-Electric Boost Mode is gated off fleet-wide behind all_e_boost_mode. The code is in app v1.59.0 and Cloud v2.42.0, but customers cannot reach it yet.
    Impact for CS: no customer action — Boost Mode is not live. The /me boost security fix (QPD-14740) is backend-only.

    QPD-14022 · ALL-E | Commissioning & B2B Enhancements 7 tickets

    The programme to let external B2B partners commission and service All-Electric systems without Quatt Field Ops support — commissioning improvements aimed at lifting external self-completion toward 80%.

    • M6 three-way-valve position check — end-to-end this wave: the CiC maps the three_way_valve_heatcharger mode and reports it in stats (QPD-14061 Systems Control); the backend position check replaces the Boost test, gated on CiC firmware 4.10.0 (QPD-14402 Cloud / Backend); new app test screen (QPD-14403 App)
    • CH backup-heater test: a temperature-based test screen in the app (QPD-14902 App), validated on the backend by a temperature-rise (ΔT) check (QPD-14060 Cloud / Backend)
    • HeatCharger firmware supporting work: flash read-out protection (QPD-13854 Embedded Systems) and CH pressure-noise handling via an 80-sample filter (QPD-13867 Embedded Systems)
    Impact for installers: the All-Electric commissioning flow replaces the Boost step with a direct 3-way-valve position check. Because the backend gate targets CiC 4.10.0, it activates only on installations on the 4.10.0 line (with app v1.59.0) — this is the wave that makes the replacement functional end-to-end.

    QPD-11795 · CHILL | Field Test Stability Improvement 6 tickets

    Stability work for Chill pilot installations — fixing Chill and dongle bugs that fall outside current feature development, and supporting new customer pilots.

    • CHILL flow test: add flow-test validation (QPD-14263 Cloud / Backend) and fail on flow-switch protection rather than raw fault flags (QPD-14986 Cloud / Backend)
    • Commissioning firmware handling: backend auto-trigger for CiC firmware deployment + retry endpoint (QPD-14485 Cloud / Backend), surfaced in the app as a “preparing” state with a failed-state retry (QPD-15005 App)
    • Diagnostics: add Thread connection status to diagnostics (QPD-14555 Cloud / Backend); fix the Chill CS dashboard not showing the correct unit state (QPD-14901 SW&I)
    Impact for CS / installers: the CS dashboard now reflects the correct Chill unit state, and commissioning can bring the CiC to the required firmware automatically with a retry path if it fails.

    QPD-11880 · Bug Fixing & Fleet Diagnostics 4 tickets

    The controls team’s rolling bug-fixing and fleet-diagnostics Epic. This wave’s headline is the Chill cooling regression fix.

    • Chill cooling regression fixed: the outdoor unit now enters cooling on the actual house heating demand rather than the raw OpenTherm CH-enable bit. Some thermostats (e.g. Remeha Celcia 20) hold CH-enable asserted year-round, which had left the water temperature running away (observed 24 → 33 °C in ~30 min). Regression from CiC 4.8.0 (QPD-15262 Systems Control)
    • Read a sub-zero (freezing) suction temperature as a valid, signed value so the suction-unsafe condition is no longer missed — spanning the HeatCharger firmware, the message spec and the CiC apps (QPD-11712 Embedded Systems)
    • Controller refinements with no ticket: a compressor safety cooldown is no longer reported as degraded service; higher commissioning frequency in the low-level controls
    • HeatCharger firmware CI hardening: self-host devcontainer images (QPD-13746 Embedded Systems); fix flaky unit tests (mock lifetime vs process shutdown) (QPD-13749 Embedded Systems)
    Impact for installers / CS: the Chill cooling fix (QPD-15262) resolves NCR-3862 — 6 Chill systems where cooling water temperature could run away with certain thermostats. It already reached the fleet via the 4.9.1 hotfix (Controller 6.10.3) and is carried forward here. This beta build goes only to beta testers.

    QPD-13717 · ZipIt: Telemetry Firehose + Parquet Pipeline 4 tickets

    The telemetry-pipeline overhaul (ZipIt): replacing the per-CiC S3 file layout (~60M files/month) with a compacted Firehose → Lambda → Parquet+GZIP pipeline, queryable via Athena and ClickHouse. This wave is production-rollout tuning.

    • Telemetry-transform Lambda memory raised 128 → 256 MB for the rollout (QPD-15130 Cloud / Backend); Firehose buffer sizing fixed to clear 413 payload errors (QPD-15150 Cloud / Backend); Lambda migrated to arm64/Graviton (QPD-15270 Cloud / Backend); compression-ratio metrics emitted via CloudWatch EMF (QPD-14900 Cloud / Backend)
    Impact for ops: the ZipStats rollout reduces telemetry cost and payload size as it reaches the fleet — watch the telemetry-transform metrics during rollout.
