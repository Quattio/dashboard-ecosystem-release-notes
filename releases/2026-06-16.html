1 · CiC memory-leak hotfix (cic-cloud-command) Bug Fixing & Fleet Diagnostics

  • Regression from 4.7.0. The 4.7.0 WiFi-command port from Python to C++ libnm (QPD-14148) left the libnm NMClient's private GMainContext serviced only inside a WiFi command handler. Between commands — the normal steady state — NetworkManager D-Bus signal sources (AP scans, periodic signal-strength updates) queued up and were never drained, so cic-cloud-command RSS ratcheted up monotonically. (QPD-14564, Urgent)
  • Field impact. On 4.7.x the per-CiC minimum free memory dropped from ~180 MB (4.5/4.6) to as low as 16–90 MB; roughly 19% of 4.7 CiCs fell below 30 MB free (vs ~0% on 4.5/4.6). Under that pressure cic-controller overran its loop and OpenTherm bit-timing broke — the likely driver of the "boiler runs in CH mode with no demand" reports and the CiC reboots.
  • Fix. The WiFi context is now pumped (bounded drain) from the single-threaded redis-listen watchdog that already ticks at least every 2 s, so queued signals are drained continuously. No new threads, no locks; peak live-set bounded to ~2 s of NetworkManager signals. x86 build + 62 existing tests green; hardware A/B confirmed the drain stops the growth.
Impact for CS / ops: this is the fix for the "boiler heats in CH mode with no demand" + frequent-reboot symptom on 4.7.x fleets (incident NCR-3548; tracked behaviour QPD-14550). CICs on 4.7.0/4.7.1 showing low free memory, repeated reboots, or unexplained boiler-CH events should be prioritised onto this build. After rollout, watch the fleet min-free-memory metric (Snowflake fct_cic_stats) return toward the ~180 MB 4.5/4.6 baseline.

Related / context

  • Caused by / regression of: QPD-14148 ("Port WiFi command handlers Python → C++ libnm", shipped 4.7.0).
  • Causes / blocks: QPD-14550 ("boiler triggered randomly since 4.7.1", N/A fixVersion) and incident NCR-3548.
  • A milder, separate instability seen on 4.6 predates the WiFi port and is tracked as a possible second contributor — not addressed by this hotfix.
