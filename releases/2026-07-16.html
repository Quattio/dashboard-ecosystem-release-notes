1 · Controller 6.11.2 — Chill cooling regression fix & control refinements new in alpha.1 Controls | Bug Fixing & Fleet Diagnostics

  • Chill cooling regression fixed: the outdoor unit now enters cooling based on the actual house heating demand rather than the raw OpenTherm CH-enable bit. Some thermostats (e.g. Remeha Celcia 20) hold CH-enable asserted year-round with no heat demand, which had left the outdoor unit stuck in circulation while the Chill kept cooling — letting the water temperature run away (observed 24 → 33 °C in ~30 min). Regression introduced in CiC 4.8.0; this restores the correct pre-4.8.0 behaviour (QPD-15262, High)
  • A compressor safety cooldown is no longer reported as degraded service (controller fix, no ticket)
  • Higher commissioning frequency in the low-level controls (controller fix, no ticket)
Impact for installers / CS: the Chill cooling fix (QPD-15262) resolves a known field issue (NCR-3862) affecting 6 Chill systems where cooling water temperature could run away with certain thermostats. It ships here in the bundled Controller firmware, but this CiC build is an alpha and is not on the fleet — the fix reaches customers only once the 4.10.0 line is promoted to a fleet release. Do not communicate the alpha firmware behaviour to customers or installers.

2 · HeatCharger firmware 1.3.0 — All-Electric field reliability & safety HeatCharger | Firmware

  • Enforce a 2-minute minimum compressor on-time and improve central-heating pressure-noise handling (widened to an 80-sample filter) (QPD-13439, QPD-13867)
  • Read a sub-zero (freezing) suction temperature as a valid, signed value so the suction-unsafe condition is no longer missed — spanning the HeatCharger firmware, the message spec and the CiC apps (QPD-11712, High)
  • Activate the warning LED on a 3-way-valve error and treat an Undefined valve state as unsafe (QPD-13979)
  • Firmware-update robustness: word/block flash programming (faster, less wear) and flash read-out protection (QPD-14524, QPD-13854)
Impact for installers / CS: a reliability and safety pass on the HeatCharger (the indoor unit that replaces the boiler on All-Electric systems). The 3-way-valve warning-LED item (QPD-13979) was held back in the 4.9.0 wave because its HeatCharger-firmware counterpart had not shipped — that counterpart ships here, so the feature is now functional end-to-end.

3 · Three-way-valve commissioning check Commissioning

  • New app 3-way-valve position check test screen, replacing the old Boost test (QPD-14403, QPD-14061, High)
  • The CiC maps the three_way_valve_heatcharger commissioning mode and reports it in the stats stream (QPD-14061)
Impact for installers: the All-Electric commissioning flow replaces the Boost step with a direct 3-way-valve position check. Needs the paired app v1.59.0 and this CiC build (or a later non-alpha build carrying the same apps).

4 · Commissioning UX App | Commissioning

  • The app now surfaces a cloud-initiated CIC firmware deployment during commissioning (a “preparing” state plus a failed-state retry) (QPD-15005, Urgent)
  • The Cancel-commissioning button now warns the installer that cancelling leaves the system non-working (QPD-14616, Urgent)
  • Restore the CIC-specific copy on the pre-identification firmware-update screen (QPD-14468); new temperature-based CH backup-heater test screen (QPD-14902)
  • Removed the legacy (non-beta) hybrid commissioning screens and their E2E flow (QPD-7507, QPD-7509, QPD-15007)
Impact for installers: clearer commissioning guidance and a smoother firmware-update-during-commissioning experience. The legacy hybrid commissioning path is now fully retired in favour of the HYBRID_BETA flow.

5 · Predictive heating (MPC) — controller groundwork Controls | Predictive Heating

  • Add a terminal cost to the predictive-heating MPC (Model Predictive Control) (QPD-15003)
  • Complete boost-mode exit-reason and recoverable-condition reporting in the controller (QPD-15024)
Shipped but not live — do not communicate to customers: this continues the predictive-heating groundwork begun in the 4.9.0 wave. It is not enabled for the fleet and does not change how any customer’s system heats today.

6 · Environment sensors over Thread — data groundwork Wireless Platform | Sensors

  • The Quatt dongle now exposes its temperature / humidity readout over the Spinel vendor property in RCP mode, and the CiC reads it (QPD-14888)
Impact for ops: extends the environment temperature / humidity data-collection groundwork started in the 4.9.0 wave to the RCP (radio co-processor) dongle role. Data-collection only — not surfaced to customers.

7 · Shipped but DISABLED — do not communicate to customers or installers App | All-Electric & Insights

  • Insights V2 — the Insights charts are rebuilt on victory-native XL and the legacy cards/banner ported to modern components, all behind the insights_v2 feature flag (off for customers). Includes new touch tooltips and unified chart gestures (QPD-14773, QPD-14881, QPD-14880, QPD-14945, QPD-14975)
  • All-Electric Boost Mode continues to evolve behind its all_e_boost_mode flag: the never-emitted DEGRADED status is removed (app + message spec) and the app reads live All-E fields from the boost response instead of polling the CiC (QPD-14892, QPD-14299, QPD-14223)
Shipped but DISABLED — do not communicate until the flag is enabled: both Insights V2 (insights_v2) and All-Electric Boost Mode (all_e_boost_mode) are gated off in production. The code is in app v1.59.0 but customers cannot reach these screens yet.

8 · App & CiC maintenance Maintenance

  • App: explicit splash-driven startup / auth state machine (AppPhase) (QPD-14408); migrate the legacy legacy/api, MobX store, app-compatibility check and RegistrationInstallerId screen to modern patterns (QPD-14769, QPD-14770, QPD-14771, QPD-14772, QPD-15004); victory-native XL bump (QPD-14703)
  • Fixes: the app measurement-locale bug (QPD-14955) and the “Fair” signal-strength mistranslation in NL/DE/SK (QPD-14778) (both customer-visible — see the Customer tab)
  • CiC: fix forget_wifi returning “bad” for a just-connected SSID (libnm connection cache not drained before lookup) (QPD-14979); cross-compile all C++ apps against the Yocto SDK dev container (QPD-15050)
  • Message spec: Chill dew-point correction groundwork — Redis keys added ahead of the controller logic, which is not yet in this wave, so dew-point protection is not yet functional (QPD-14756)
Impact for ops: mostly internal refactoring and two customer-visible app fixes. The Chill dew-point keys are spec-only groundwork; do not present dew-point protection as a live feature until the controller side ships.
