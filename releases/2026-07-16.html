Reviewer feedback revision (PR #26) — App v1.60.0 now paired. Per Alex’s request, App v1.60.0 (shipped 2026-07-24, one day past the auto-computed +7d tail) is now paired to this 4.10.0 wave alongside v1.59.0. v1.60.0 removes the app-side gates — QPD-14883 drops the insights_v2 flag and the legacy Insights code, and QPD-14724 drops the all_e_boost_mode flag and the legacy V1 HeatBattery screen — and QPD-15101 redesigns the Sound settings screen with separate day/night modes. CiC / firmware content is still identical to the beta entry. Pairing v1.60.0 changes only the App surface — the CiC 4.10.0 tag still points at the same commit as 4.10.0-beta.0 (1c134b9) and all bundled firmware is unchanged. Nothing was reverted or removed.

    This ecosystem update brings the CiC 4.10.0 firmware to the general fleet as a stable release. Everyday heating and comfort behaviour on the CiC is unchanged; the customer-visible changes below arrive with the Quatt app updates (versions 1.59.0 and 1.60.0).

    Heating performance and reliability

    • All-Electric systems can now use Boost Mode: when the HeatBattery is low, you can quickly restore enough hot water for at least one shower, prioritising heating speed over efficiency.
    • Sound settings now let you set separate day and night modes, so your outdoor unit can run more quietly during the hours you choose.
    • Everyday central-heating and comfort behaviour is otherwise unchanged in this release.

    Bug fixes and maintenance

    • The energy insights screens in the app have been rebuilt with clearer charts and smoother touch interactions.
    • Measured values such as temperatures now follow your app’s language setting consistently.
    • General reliability and maintenance improvements.

    QPD-11732 · All-E | Boost Mode Feature 14 tickets

    Boost Mode lets an All-Electric system quickly restore hot water for at least one shower (within ~15 min) when the HeatBattery is depleted — heating speed over efficiency. This wave refines the round-trip UX, adds a security fix, lands controller-side reporting, and — with the newly-paired app v1.60.0 — turns the feature on by removing the app-side gate.

    • Round-trip UX (backend, Cloud v2.42.0): optimistic Boost/Leave-Boost status (QPD-14742 Cloud / Backend), live All-Electric fields surfaced in the boost response (QPD-14222 Cloud / Backend), Live View on START/CANCEL (QPD-14788 Cloud / Backend), outcome tombstoning against a stale exitReason (QPD-14817 Cloud / Backend), time-based shower-minutes bonus while the tank sensor lags (QPD-14747 Cloud / Backend)
    • App + spec: read live All-E fields from the boost response instead of polling the CiC (QPD-14223 App); remove the never-emitted DEGRADED status across app, message spec and backend (QPD-14892 App, QPD-14299 Cloud / Backend)
    • Controller: complete boost-mode exit-reason and recoverable-condition reporting (QPD-15024 Systems Control)
    • Security: enforce CiC ownership on the /me boost action route (QPD-14740 Cloud / Backend)
    • Rollout: production minimum CiC version for boost stays at 4.9.0 — a bump to 4.10.0 was raised and reverted (QPD-15022 Cloud / Backend)
    • Enabled in app v1.60.0: remove the all_e_boost_mode gate and delete the legacy V1 HeatBattery screen so the Boost / HeatBattery V2 screen is the only one (QPD-14724 App); handle the AWAITING_CIC_STATE state and show a delayed-start banner on STARTING (QPD-15257 App); soften the “bottom tank still hot” banner (copy + no icon) (QPD-15322 App)
    Impact for CS: All-Electric Boost Mode is now live — app v1.60.0 removes the all_e_boost_mode gate and the backend minimum CiC version (4.9.0) is met on the 4.10.0 line, so All-Electric customers on 4.9.0+ can now use Boost. The /me boost security fix (QPD-14740) is backend-only.

    QPD-11880 · Bug Fixing & Fleet Diagnostics 4 tickets

    The controls team’s rolling bug-fixing and fleet-diagnostics Epic. This wave’s headline is the Chill cooling regression fix.

    • Chill cooling regression fixed: the outdoor unit now enters cooling on the actual house heating demand rather than the raw OpenTherm CH-enable bit. Some thermostats (e.g. Remeha Celcia 20) hold CH-enable asserted year-round, which had left the water temperature running away (observed 24 → 33 °C in ~30 min). Regression from CiC 4.8.0 (QPD-15262 Systems Control)
    • Read a sub-zero (freezing) suction temperature as a valid, signed value so the suction-unsafe condition is no longer missed — spanning the HeatCharger firmware, the message spec and the CiC apps (QPD-11712 Embedded Systems)
    • Controller refinements with no ticket: a compressor safety cooldown is no longer reported as degraded service; higher commissioning frequency in the low-level controls
    • HeatCharger firmware CI hardening: self-host devcontainer images (QPD-13746 Embedded Systems); fix flaky unit tests (mock lifetime vs process shutdown) (QPD-13749 Embedded Systems)
    Impact for installers / CS: the Chill cooling fix (QPD-15262) resolves NCR-3862 — 6 Chill systems where cooling water temperature could run away with certain thermostats. It already reached the fleet via the 4.9.1 hotfix (Controller 6.10.3) and is carried forward on the 4.10.0 line here.
