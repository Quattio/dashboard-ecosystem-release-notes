1 · Controller 6.11.2 — Chill cooling regression fix & control refinements Controls | Bug Fixing & Fleet Diagnostics

  • Chill cooling regression fixed: the outdoor unit now enters cooling based on the actual house heating demand rather than the raw OpenTherm CH-enable bit. Some thermostats (e.g. Remeha Celcia 20) hold CH-enable asserted year-round with no heat demand, which had left the outdoor unit stuck in circulation while the Chill kept cooling — letting the water temperature run away (observed 24 → 33 °C in ~30 min). Regression introduced in CiC 4.8.0; this restores the correct pre-4.8.0 behaviour (QPD-15262, High)
  • A compressor safety cooldown is no longer reported as degraded service (controller fix, no ticket)
  • Higher commissioning frequency in the low-level controls (controller fix, no ticket)
Impact for installers / CS: the Chill cooling fix (QPD-15262) resolves a known field issue (NCR-3862) affecting 6 Chill systems where cooling water temperature could run away with certain thermostats. The same fix already reached the fleet via the 4.9.1 hotfix (Controller 6.10.3); here it is carried forward on the 4.10.0 line. This beta CiC build goes only to beta testers, so do not communicate its firmware behaviour to the wider customer base or installers.

2 · HeatCharger firmware 1.3.0 — All-Electric field reliability & safety HeatCharger | Firmware

  • Enforce a 2-minute minimum compressor on-time and improve central-heating pressure-noise handling (widened to an 80-sample filter) (QPD-13439, QPD-13867)
  • Read a sub-zero (freezing) suction temperature as a valid, signed value so the suction-unsafe condition is no longer missed — spanning the HeatCharger firmware, the message spec and the CiC apps (QPD-11712, High)
  • Activate the warning LED on a 3-way-valve error and treat an Undefined valve state as unsafe (QPD-13979)
  • Firmware-update robustness: word/block flash programming (faster, less wear) and flash read-out protection (QPD-14524, QPD-13854)
Impact for installers / CS: a reliability and safety pass on the HeatCharger (the indoor unit that replaces the boiler on All-Electric systems). The 3-way-valve warning-LED item (QPD-13979) was held back in the 4.9.0 wave because its HeatCharger-firmware counterpart had not shipped — that counterpart ships here, so the feature is now functional end-to-end.

3 · Three-way-valve commissioning check — now end-to-end backend added in beta Commissioning

  • New app 3-way-valve position check test screen, replacing the old Boost test (QPD-14403, QPD-14061, High)
  • The CiC maps the three_way_valve_heatcharger commissioning mode and reports it in the stats stream (QPD-14061)
  • Backend side (Cloud v2.42.0): the commissioning 3-way-valve position check replaces the Boost test on the server and is gated on CiC firmware 4.10.0 (QPD-14402, Urgent); the Chill flow test now validates against flow-switch protection rather than raw fault flags (QPD-14263, QPD-14986)
Impact for installers: the All-Electric commissioning flow replaces the Boost step with a direct 3-way-valve position check. Because the backend gate targets CiC firmware 4.10.0, this check only activates on installations running the 4.10.0 line (with the paired app v1.59.0) — it is the wave that makes the replacement functional end-to-end.

4 · Commissioning UX App | Commissioning

  • The app now surfaces a cloud-initiated CIC firmware deployment during commissioning (a “preparing” state plus a failed-state retry) (QPD-15005, Urgent), backed by a Cloud auto-trigger for CiC firmware deployment + retry endpoint (QPD-14485)
  • The Cancel-commissioning button now warns the installer that cancelling leaves the system non-working (QPD-14616, Urgent)
  • Restore the CIC-specific copy on the pre-identification firmware-update screen (QPD-14468); new temperature-based CH backup-heater test screen (QPD-14902), validated on the backend by a temperature-rise (ΔT) check (QPD-14060)
  • Removed the legacy (non-beta) hybrid commissioning screens and their E2E flow (QPD-7507, QPD-7509, QPD-15007)
Impact for installers: clearer commissioning guidance and a smoother firmware-update-during-commissioning experience — the CiC can now be brought to the required firmware automatically during commissioning. The legacy hybrid commissioning path is now fully retired in favour of the HYBRID_BETA flow.

  • Backend (Cloud v2.42.0): the platform now ingests the Thread device temperature & humidity sensor readings, completing the collection path from dongle to cloud storage
Impact for ops: extends the environment temperature / humidity data-collection groundwork started in the 4.9.0 wave to the RCP (radio co-processor) dongle role, and the readings are now stored in the cloud. Data-collection only — not surfaced to customers.

9 · Backend platform — Cloud v2.42.0 new in beta Quatt Cloud

  • ZipStats production rollout (telemetry pipeline): the compressed-telemetry path is being tuned for the fleet — telemetry-transform Lambda memory raised for the rollout, Firehose buffer sizing fixed to clear 413 payload errors, migration to arm64/Graviton, and compression-ratio metrics emitted via CloudWatch (QPD-14900, QPD-15130, QPD-15150, QPD-15270)

Do not communicate it externally.

  • Performance / maintenance: fetch the CiC row once per stats message instead of three times (QPD-14885); dependency update sweep (QPD-14097)
Impact for ops / CS: the ZipStats rollout reduces telemetry cost and payload size as it reaches the fleet — watch the telemetry-transform metrics.
