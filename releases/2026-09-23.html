    QPD-148 · MPC predictive heating 14 tickets

    Model Predictive Control for central heating — cloud-trained house-dynamics models served to the controller. This wave lands the backend plumbing to turn predictive heating on for a pilot cohort: the setting end-to-end, admin controls, thermostat-schedule constraints, the avoid-gas-boiler setting, and the message-spec schema they ride on. All Cloud v2.48.0, except the message-spec change which is also bundled in the CiC image.

    • Predictive-heating setting & pilot enablement: predictiveHeatingEnabled stored, exposed on /me REST and sent via cmd/req/settings (QPD-15828 Cloud / Backend); enabled for the pilot cohort via a one-off script (QPD-15847 Cloud / Backend)
    • Admin controls: read the thermostat schedule (QPD-15913 Cloud / Backend), switch predictiveHeatingEnabled (QPD-15915 Cloud / Backend), and toggle pilot participation from the support dashboard (QPD-15880 Cloud / Backend)
    • Thermostat schedule handling: enforce a strict 0.5 °C grid on setpoints (QPD-15870 Cloud / Backend); prompt to add schedule blocks when predictive heating is turned on with an empty schedule (QPD-15879 Cloud / Backend); stop the grid pilot scripts from clearing thermostat schedules (QPD-15827 Cloud / Backend); fix a payload that sent liveOverride, which the merged CiC schema forbids (QPD-15848 Cloud / Backend)
    • avoid-gas-boiler: avoidGasBoilerUse setting end to end (QPD-15829 Cloud / Backend); exposed to non-predictive Hybrid CiCs above a minimum firmware build (QPD-15947 Cloud / Backend); reactive avoid-gas-boiler enabled on develop only (QPD-16006 Cloud / Backend)
    • Message spec: remove the double nesting from the thermostatSchedule schema (bundled message spec 2.85.2) (QPD-15998 Cloud / Backend)
    Shipped but pilot / not fleet-wide — do not communicate: predictive heating is enabled only for the pilot cohort, and reactive avoid-gas-boiler is on develop only. Neither is a general-customer feature yet.
    Impact for CS: predictive heating is live for the pilot cohort only; nothing changes for other customers. Support can toggle a pilot installation’s participation from the dashboard.

    QPD-11880 · Bug Fixing & Fleet Diagnostics 4 tickets

    The embedded team’s rolling bug-fixing and fleet-diagnostics Epic. This wave: a factory-reset fix, a config-delivery fix, message-spec robustness, and OTA retry backoff — all riding the CiC 4.15.0-alpha.0 build.

    • Factory reset fixed: quatt-factory-reset used an invalid systemctl stop --timeout option, so it never actually stopped the owner services during a factory reset — corrected (QPD-15989 Embedded Systems)
    • Config delivery fixed: nested config objects (e.g. the predictive-heating dual-rate model) were never written to their Redis key, so the controller never received them — fixed in controller-manager 3.19.2 (QPD-16011 Embedded Systems)
    • Message-spec robustness: ensure new settings / configs are nullable, so the cloud can send an unset value without the whole payload being rejected (message spec 2.85.2) (QPD-15929 Embedded Systems)
    • OTA retry backoff: OTA update-cycle retries had no delay, so 20 cycles could burn in ~2 seconds and turn a transient “not now” into a permanent failure — the OTA library now backs off between retries (bundled via embedded apps 1.37.1) (QPD-15978 Embedded Systems)
    • Diagnostics (no ticket): every Axiom log record is now stamped with the CiC version, so fleet logs are attributable to a firmware version
    Impact for ops: these fix real field and diagnostic failure modes (factory reset not stopping services, config not reaching the controller, OTA updates failing instantly). They ride the CiC 4.15.0-alpha.0 build, so they reach the alpha track first, not the general fleet, this wave.
